# Media Grabber

这是一个装进 Chrome 或 Edge 的小工具。打开带视频或音频的网页，点一下工具栏图标，就能看到页面里的音视频地址，复制链接，或者把能直接保存的文件下载下来。

它不破解 DRM，也不帮你绕过付费或登录。HLS 里那种标准的 AES-128（密钥就是一个能直接打开的 16 字节文件）可以下载。

## 能做什么

- 找出当前标签页里的视频、音频，以及 HLS / DASH 清单地址。
- 列表里显示类型、大小（没有大小就显示「未知」）和地址。
- 每条都可以复制完整链接。
- mp4、webm、mp3、m4a 这类直链可以下载到系统的下载文件夹。
- 未加密的 HLS 点播（m3u8）可以下载。标准 AES-128 的点播也可以：扩展会自己去取 16 字节密钥，在内存里解密，再把 TS 转封装成 `.mp4`。有多种清晰度时先选一条，默认是最高的。分片按顺序拼成一个文件。带初始化段的 fMP4 直接存成 `.mp4`。AES-128 如果同时还带初始化段，这一版不做。
- 未加密的 DASH 点播（mpd）可以下载。多种清晰度时先选，默认是最高的视频。视频和音频通常是分开的，下载后默认合并成一个 `.mp4`。合并失败、两路合计超过 1GB，或勾选「分开保存视频和音频」时，仍保存成两个文件（`.mp4` 和 `.m4a`）。
- B 站视频页可以下载当前能播放的分轨文件。视频行有「下载视频」和「下载音频」。「下载视频」带上码率最高的音频，默认合并成一个 `.mp4`；勾选「分开保存视频和音频」则视频存 `.mp4`、音频存 `.m4a`。「下载音频」只保存 `.m4a`。音频行只有「下载音频」。页面没有音频时，「下载视频」只下无声视频，并写明没找到音频。
- 下载开始后，条目上显示进度或「已开始下载」，下完显示「已完成」。失败会写出原因，关掉弹窗再打开还能看到最近一次。

## 不做什么

- **不处理 DRM。** Netflix 这类用 Widevine、PlayReady 或 FairPlay 的视频，扩展不会去破解。清单里出现这些加密方式时，会用中文拒绝。
- **不绕过付费、登录或会员限制。** 普通直链、HLS（含 AES-128 取密钥）和 DASH 不改请求头。AES-128 的密钥也是普通请求去拿，服务器返回 401 或 403 就停下来。只有 B 站分轨下载会给扩展自己的请求补上页面 Referer，而且只下这个页面现在就能播的内容。详见下面的权限说明。
- **不下载 SAMPLE-AES，也不下载直播。** HLS 的 `SAMPLE-AES`、密钥格式不是 identity、没有结束标记，以及 DASH 里的 `ContentProtection` 或 `type="dynamic"`，都会用中文拒绝。标准 AES-128 点播不在拒绝之列。
- **HLS 里单独的音轨清单不合并。** DASH 和 B 站的两路 fMP4 默认会在本地合成一个 `.mp4`，不重新编码。mux.js 合并不了这种文件，用的是扩展自己的合并器。加密轨、多轨、合计超过 1GB，或合并失败时，改回分开保存。
- **不重新编码。** TS 只做转封装。H.265、AC-3 这类转不了的编码会留下 `.ts`。已经是 fMP4 的流不会再转一次。
- **不支持 Safari。** 目前只做 Chrome 和 Edge。

## 你需要先准备

- 一台能装 Chrome 或 Edge 的电脑。
- Node.js：**20.19.0 或更新的 20.x**，或者 **22.12.0 及以上**（Node 24 可以用）。不要用 Node 21，它不在这个范围里。

查看版本：在终端里输入 `node -v`。如果版本不对，去 [nodejs.org](https://nodejs.org/) 安装一个符合要求的版本，装完重新打开终端再查一次。

版本太旧时，后面的构建会报找不到 `rolldown-binding`。那是打包器自带的文件，不是你少下了别的东西，把 Node 换成上面的版本即可。

## 在 Windows PowerShell 里安装和构建

1. 安装好 Node.js（见上一节）。
2. 打开项目文件夹。可以在资源管理器地址栏输入 `powershell` 后回车，这样终端已经位于项目目录。
3. 确认版本，然后安装依赖并构建：

```powershell
node -v
npm install
npm run build
```

构建成功后，项目里会出现 `dist` 文件夹。下一步要加载的就是它。

如果 PowerShell 弹出下面这种提示，是 Windows 的执行策略拦住了 `npm.ps1`，不是项目坏了：

```text
无法加载文件 C:\Program Files\nodejs\npm.ps1，因为在此系统上禁止运行脚本。
```

任选一种处理：

- 只给当前用户放开本地脚本（推荐）。执行下面这一行，关掉 PowerShell 再打开，然后重新 `npm install`：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

- 不想改策略的话，改用 cmd 版的 npm，后面的命令也写成 `npm.cmd`：

```powershell
npm.cmd install
npm.cmd run build
```

macOS 和 Linux 没有这条执行策略。打开「终端」，`cd` 到项目目录，同样执行 `npm install` 和 `npm run build`。

## 加载到浏览器

Chrome 和 Edge 都不能直接双击 zip 安装。要加载的是一个文件夹。

1. 地址栏输入 `chrome://extensions` 后回车。Edge 则输入 `edge://extensions`。
2. 打开右上角的「开发者模式」。
3. 点「加载已解压的扩展程序」。
4. 选中项目里的 **`dist`** 文件夹。不要选仓库最外层的文件夹。
5. 列表里出现 **Media Grabber**（版本 0.2.3）。如果工具栏没看到图标，点拼图图标，把它固定出来。加载时会多问一项「读取并修改网络请求」一类的权限，那是 B 站下载用来补 Referer 的，范围见下文。

想发给自己另一台电脑时，可以先打包：

```powershell
npm run package
```

它会先构建，再在 `release` 里生成 `media-grabber-0.2.3.zip`。zip 的根目录就是 `manifest.json`。把 zip 解压，然后对解压出来的文件夹再做一次「加载已解压的扩展程序」。`release` 不会提交到 git。

## 怎么用

1. 打开一个有视频或音频的网页，让它播放一下。
2. 点工具栏上的 Media Grabber。
3. 弹窗里列出找到的资源。能下载的排在前面，blob 这类不能下的在后面。下载过程中这个顺序不会跳。地址太长会被截断，鼠标停在上面能看全文。
4. 点「复制」，完整链接会进剪贴板，按钮会短暂显示「已复制」。
5. 普通直链旁边有「下载」。文件名来自页面标题；标题不能用时，用链接里的文件名。系统里已有同名文件时，浏览器会自动改名，不会覆盖。
6. HLS 清单旁边也有「下载」。如果这是一份包含多种清晰度的主清单，会先让你选，默认停在最高的一条，再点「开始下载」。进度条显示已经下了多少片。分片下完后，普通 TS 会显示「正在转成 mp4…」。可以点「取消」。关掉弹窗再打开，进度还在。转成功的文件是 `.mp4`。转失败会留下 `.ts`，并写明可以用 VLC 播放。标准 AES-128 的清单同样有下载按钮，条目上会写「含 AES-128 加密」。密钥或 IV 不对时，会写「解密失败（密钥或 IV 不对）」，不会保存密文。
7. DASH 清单旁边同样有「下载」。多种清晰度时先选，默认是最高的视频。进度和取消跟 HLS 一样。视频和音频分开时，下完会显示「正在合并…」，成功后是一个 `.mp4`。弹窗顶部可以勾选「分开保存视频和音频」。
8. B 站视频页会列出「B站视频 …」和「B站音频 …」。视频行点「下载视频」，会带上码率最高的音频，默认合并成一个 `.mp4`；点「下载音频」只保存 `.m4a`。音频行只有「下载音频」。页面里没有音频时，「下载视频」只下无声视频，说明里会写没找到音频。先让视频播起来再打开弹窗。链接有有效期，失效后先刷新页面再点下载。会员专享或服务器返回 403 时，弹窗用中文说明失败，不会再换办法去下。
9. 点「清空」只清掉**当前标签页**的记录。换一个标签页，列表也换成那一页的。

`blob:` / `data:` 地址没有下载按钮，旁边会写原因。YouTube 这类播放器看到的是 blob，真实文件是分片，这一版下不下来。B 站的 blob 本身也不下，能下的是页面脚本或 CDN 上的分轨文件。直播、SAMPLE-AES 或带 DRM 的 m3u8，以及加密或直播的 mpd，点了下载也会停下来，并写出原因。

## 自己验一条 AES-128

没有放一个固定的公开测试地址，避免链接失效以后对不上。在空目录里自己生成一条（需要本机有 ffmpeg）：

```powershell
openssl rand 16 > enc.key
ffmpeg -f lavfi -i testsrc=size=320x180:rate=25 -f lavfi -i sine=frequency=440:sample_rate=48000 -t 6 -c:v libx264 -pix_fmt yuv420p -c:a aac -hls_time 2 -hls_playlist_type vod -hls_enc 1 -hls_enc_key enc.key -hls_enc_key_url enc.key -hls_segment_filename "seg%03d.ts" index.m3u8
python -m http.server 8080
```

再做一个本地网页，写上 `<video src="http://127.0.0.1:8080/index.m3u8" controls></video>`，用 Chrome 或 Edge 打开。浏览器不一定能直接播放这份 m3u8，扩展仍然会列出这个地址。

预期：

- 弹窗里这条 HLS 可以下载，并写着「含 AES-128 加密」。
- 下完得到 `.mp4`。转封装失败时是 `.ts`，条目会说明可以用 VLC 播放。那份 `.ts` 已经解密。
- 把密钥文件挪走，或让密钥地址返回 403，弹窗用中文说明获取密钥失败。扩展不会为 HLS 改 Referer，也不会加别的请求头。
- SAMPLE-AES、FairPlay、Widevine、PlayReady 的清单点下载后停下来，并写出原因。

AES-128 这一步没有新的扩展权限。B 站分轨用的权限见下文。

## 已知限制

- **DASH 只下未加密的静态点播。** 支持 SegmentTemplate 和 SegmentList，初始化段会拼在分片前面。视频和音频默认合并成一个 `.mp4`，不重新编码。合并失败、合计超过 1GB，或勾选「分开保存视频和音频」时，视频存 `.mp4`、音频存 `.m4a`，条目上会写明原因。直播（`type="dynamic"`）、`ContentProtection`、多个 Period、字幕轨，以及需要 `Range` 请求头的 SegmentBase，都会用中文拒绝。WebM 清单也不下。分片本身不会单独列在列表里。
- **标准 AES-128 可以下，别的 HLS 加密不行。** 只接受 `METHOD=AES-128`、密钥格式是 identity（或不写）、密钥地址是 http 或 https、密钥正好 16 字节。解密用浏览器自带的 AES-CBC，密钥和明文只留在内存里，不写进扩展存储，也不显示在弹窗上。弹窗只写「含 AES-128 加密」。SAMPLE-AES、FairPlay、Widevine、PlayReady 会用中文拒绝。带初始化段的 AES-128（fMP4）也不做。直播和按字节范围截取的分片仍然不做。
- **TS 转成的 mp4 是 fMP4，没有重新编码。** 用的是 mux.js，只认识 H.264 和 AAC。转失败时文件仍是 `.ts`，条目会写「转封装失败，已保存为 .ts，可用 VLC 播放」。AES-128 在这种情况下保存的是解密后的 TS。带 `EXT-X-MAP` 的 fMP4 只是把初始化段和分片按顺序接起来，没有再转一次。声音如果在另一条音轨清单里，这个文件里可能没有声音。初始化段里的时长会写成实际总时长，避免被显示成约 13 小时。系统自带播放器不一定打开这种 fMP4。
- **很大的清单会占内存。** 分片是在内存里拼完再保存的，转封装时还会再留一份 mp4。预计超过 2GB 会直接拒绝。已经超过 1GB 的 TS 不再转封装，直接存 `.ts`。分片很多或预计超过大约 512MB 时，会先提示会占较多内存。
- **有些网站的直链会 403。** 链接可能要登录、带 Cookie，或者过一会儿就失效。普通直链、HLS 和 DASH 不会改 Referer 或其他请求头。失败时弹窗写「服务器拒绝访问（403）」、哪一片缺失，或「网络连接失败」，不会一直转圈。清单地址上的 `?token=` 不会自动抄到相对路径的分片上。
- **B 站只下页面现在能播的内容。** 不支持会员专享，不处理登录墙和 DRM。「下载视频」会带上码率最高的音频，默认合并成一个 `.mp4`；勾选分开保存、合并失败或合计超过 1GB 时，仍分成 `.mp4` 和 `.m4a`。「下载音频」只存 `.m4a`。页面没有音频时，「下载视频」只下无声视频，并写明没找到音频。地址带有效期，过期后先刷新页面再下载。切换分 P 或下一个视频时，如果页面里的播放信息没更新，列表里可能只出现一条「B站 m4s 分轨文件」，并注明类型未知；下载后按文件内容决定是 `.mp4` 还是 `.m4a`。
- **Safari 暂不支持。** Firefox 也不在范围内。请用 Chrome 或 Edge。
- 关掉浏览器后，列表会被清掉。这是故意的：记录只放在这一次浏览器会话里。
- 刷新页面会清掉旧记录。网页自己换路由（地址变了但没有整页刷新）则保留。
- 大小有时是「未知」，因为服务器没告诉浏览器文件有多大。

## 项目结构

```text
media-grabber/
├── manifest.config.ts    扩展的名字、版本、权限和入口
├── package.json          依赖和命令
├── README.md             本说明
├── PLAN.md               设计说明
├── scripts/package.mjs   把 dist 打成 zip
├── public/icons/         图标
├── src/
│   ├── background/       后台：发现媒体、保存列表、写 HLS/DASH 进度、调用下载
│   ├── content/          在网页里查找 video / audio
│   ├── offscreen/        不显示的页面：拉取 HLS / DASH，解密 AES-128，下载 B 站分轨
│   ├── popup/            点图标后弹出的窗口
│   └── shared/           共用类型、HLS / DASH / AES-128、下载调度和 TS 转封装
├── tests/                自动测试
├── dist/                 npm run build 之后出现，加载这个文件夹
└── release/              npm run package 之后出现，里面是 zip
```

HLS、DASH 和 B 站分轨的下载在不显示的 offscreen 页面里完成。这个页面只能用 `chrome.runtime`。它把进度发给 service worker，由 service worker 写进 `chrome.storage.session`；拼好的 Blob 地址和文件名也发给 service worker，由 service worker 调用 `chrome.downloads` 保存。offscreen 自己不碰会话存储，也不调用下载 API，也不设置 Referer。

## 权限

安装时除了观察网络请求、下载、存储、标签页和剪贴板之外，还会要 `declarativeNetRequestWithHostAccess`。浏览器里可能显示成修改网络请求。它只做一件事：B 站分轨开始下载前，service worker 加一条**临时**会话规则，给「正在下载的那一个媒体主机」补上当前视频页的 Referer（页面地址的源站加 `/`）。

规则只匹配扩展自己发出的请求（`tabIds` 为 `-1`），资源类型只有 `xmlhttprequest`，而且只改 Referer 这一个头。下载成功、失败、取消，或者后台下载页关掉时，规则会删掉。扩展启动时也会清掉上次没删干净的同类规则。它不改你正常打开网页时的请求，也不用于 HLS（包括取 AES-128 密钥）、DASH 和普通直链，不读取 Cookie，不绕过会员限制。

## 开发命令

在项目目录执行。开发时让 `npm run dev` 一直开着，浏览器里加载的仍然是 `dist`。

| 命令 | 做什么 |
|---|---|
| `npm install` | 第一次下载依赖 |
| `npm run dev` | 开发模式。改完弹窗文案，已打开的弹窗会自己更新 |
| `npm run build` | 做出可以离线加载的 `dist`。关掉终端也能用 |
| `npm run package` | 先构建，再打出 `release/media-grabber-<版本>.zip` |
| `npm test` | 跑自动测试 |
| `npm run typecheck` | 检查 TypeScript 类型 |

想看后台有没有发现媒体：打开 `chrome://extensions`，在 Media Grabber 卡片上点「Service Worker」。播放一个带普通 mp4 的页面后，控制台里会出现 `[media-grabber] 发现媒体`。其它站点的 `.ts` / `.m4s` 分片不会被当成一条新记录。B 站 CDN 上的单个 `.m4s` 会去重后列成一条。

更细的设计见 [PLAN.md](./PLAN.md)。
